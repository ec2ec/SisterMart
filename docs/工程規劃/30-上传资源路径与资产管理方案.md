# 上傳資源路徑與資產管理方案

| 项 | 内容 |
| --- | --- |
| 状态 | 方案（待排期开刀） |
| 关联 backlog | **A7**（见 `29-剩余工作明细-M28后.md`） |
| 现状基准 | `ImageUploadService`：`/storage/{bucket}/{owner_id}/{Ymd}/{hex}.jpg` |
| 更新 | 2026-10-31 |

---

## 1. 目标

按**业务类型**规划图片上传保存路径，使上传资源可：

1. **有序**：目录一眼看出用途，不混桶  
2. **高效管理**：可按类型统计、排查、备份、清理  
3. **安全**：落库 URL 校验与类型一致，防串用  
4. **可演进**：兼容现有 `/storage/...` 与 `/api/v1/files` 代理，不一次搬家全站

非目标（本期不做）：对象存储迁移、CDN、可视化素材设计器。

---

## 2. 现状与痛点

### 2.1 现行约定

```text
public/storage/{bucket}/{owner_id}/{Ymd}/{16hex}.jpg
DB / HTML 存：/storage/...
浏览器读：{API}/api/v1/files?path=...
```

| bucket | 实际用途 | owner |
| --- | --- | --- |
| `avatar` / `review` / `aftersale` | 会员三类 | 会员 id（有前缀校验） |
| `banner` | 轮播 / 图片广告 / 活动横幅 | 管理员 id |
| `product` | 商品图 + **文章图 + 弹窗 + 券背景**（混用） | 管理员 id |
| `admin` | 富文本通用（活动介绍、注册欢迎、券规则等） | 管理员 id |

### 2.2 痛点

1. **业务类型 ≠ 目录**：文章 / 弹窗 / 券图都进 `product/`，无法按类型盘点、备份、清理。  
2. **owner 是上传人，不是实体**：不能直接找「某商品 / 某 Banner 的全部图」。  
3. **无生命周期**：换图、删商品不删文件，磁盘只增不减。  
4. **管理端无前缀校验**：会员侧严格，后台几乎任意 URL 可落库。  
5. **遗留路径**：如 `banner/20261029/*.png`（无 owner、非 jpg）与现规不一致。  
6. **无资产索引表**：只能扫盘或扫 DB/HTML，运维成本高。

## 3. 路径规范（目标态）

### 3.1 目录树

```text
/storage/
  member/
    avatar/{memberId}/{hex}.jpg          # 一人一图可覆盖；仍保留 Ymd 亦可
    review/{memberId}/{Ymd}/{hex}.jpg
    aftersale/{memberId}/{Ymd}/{hex}.jpg
  catalog/
    product/{productId|draft-{adminId}}/{Ymd}/{hex}.jpg
    category/{categoryId}/{hex}.jpg      # 分类图标（现多手填 URL）
  marketing/
    banner/{bannerId|draft-{adminId}}/{Ymd}/{hex}.jpg
    campaign/{campaignId|draft-…}/{Ymd}/{hex}.jpg
    image_ad/{adId|draft-…}/{Ymd}/{hex}.jpg
    popup/{popupId|draft-…}/{Ymd}/{hex}.jpg
    coupon/{couponId|draft-…}/{Ymd}/{hex}.jpg
    seckill/{sessionId|draft-…}/{Ymd}/{hex}.jpg   # 若有独立图
  content/
    article/{articleId|draft-…}/{Ymd}/{hex}.jpg
    richtext/{scope}/{adminId}/{Ymd}/{hex}.jpg    # 尚未绑定实体的通用富文本
  system/
    brand/{hex}.jpg                               # Logo 等极少改动
```

原则：

- **一级 = 域**（member / catalog / marketing / content / system）  
- **二级 = 类型**（与业务一一对应，禁止再混桶）  
- **三级 = 实体或 draft**（有 id 用 id；创建中用 `draft-{uploaderId}`，保存实体后再可选迁入）  
- **四级 = 日期**（便于按日归档、冷热分层；avatar / category 可省略）  
- **文件名** = `{16hex}.jpg`（继续服务端统一 JPEG）

对外 URL 仍为：`/storage/{域}/{类型}/...`，`assetUrl` / `files` 代理不变。

### 3.2 preset ↔ 路径映射

| preset（压缩策略） | 写入 bucket（路径前两段） | 调用方 |
| --- | --- | --- |
| `avatar` | `member/avatar` | H5 头像 |
| `review` | `member/review` | H5 评价 |
| `aftersale` | `member/aftersale` | H5 售后证据 |
| `product` | `catalog/product` | 商品主图/细节 |
| `banner` | `marketing/banner` / `image_ad` / `campaign` / `popup` / `coupon`（按调用传 `bucket`） | 运营位 |
| `admin`（或新 `richtext`） | `content/article` 或 `content/richtext/{scope}` | 文章 / 注册欢迎等 |
| 新增 `category`（可复用 product 压缩） | `catalog/category` | 分类图标 |

**规则**：UI 必须显式传 `bucket`（或等价 `type`），禁止「默认 product 兜底」吞掉弹窗/文章图。

### 3.3 落库校验

| 类型 | 允许前缀 |
| --- | --- |
| 头像 | `/storage/member/avatar/{memberId}/` |
| 评价 | `/storage/member/review/{memberId}/` |
| 售后 | `/storage/member/aftersale/{memberId}/` |
| 商品图 | `/storage/catalog/product/` |
| Banner / 广告 / 活动横幅 | `/storage/marketing/{banner\|image_ad\|campaign}/` |
| 弹窗 / 券图 | `/storage/marketing/{popup\|coupon}/` |
| 文章 HTML 内图 | `/storage/content/article/` 或 `content/richtext/` |

会员三类保持现有严格前缀；管理端补齐同类校验。

## 4. 资产索引（建议表）

为「有序高效管理」补一层索引（扫盘不够）：

```sql
-- 示意
CREATE TABLE upload_assets (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  path          VARCHAR(512) NOT NULL UNIQUE,  -- /storage/...
  domain        VARCHAR(32)  NOT NULL,         -- member|catalog|marketing|content|system
  asset_type    VARCHAR(32)  NOT NULL,         -- avatar|product|banner|...
  entity_type   VARCHAR(32)  NULL,             -- products|home_banners|...
  entity_id     BIGINT       NULL,
  uploader_type VARCHAR(16)  NOT NULL,         -- member|admin
  uploader_id   BIGINT       NOT NULL,
  bytes         INT          NOT NULL,
  width         INT          NULL,
  height        INT          NULL,
  status        VARCHAR(16)  NOT NULL DEFAULT 'active', -- active|orphaned|deleted
  created_at    DATETIME     NOT NULL,
  updated_at    DATETIME     NOT NULL,
  KEY idx_type_entity (asset_type, entity_type, entity_id),
  KEY idx_uploader (uploader_type, uploader_id),
  KEY idx_status_created (status, created_at)
);
```

上传成功即 insert；实体保存时回填 `entity_type/id`；删除引用时标记 `orphaned`，定时任务物理删除。

## 5. 管理能力（按优先级）

| 优先级 | 能力 | 说明 |
| --- | --- | --- |
| P0 | 新路径规范 + 调用点改 bucket | 新上传立刻分类正确 |
| P0 | 管理端落库前缀校验 | 防串桶 |
| P1 | `upload_assets` 写入 | 可统计体积/数量 |
| P1 | 后台「素材概览」只读页 | 按类型/日期汇总 |
| P2 | 孤儿扫描 + 安全清理 | 仅删无引用且超过 N 天 |
| P2 | draft → entity 路径迁入（可选） | 保存商品后把 draft 目录改名/记录绑定 |
| P3 | 遗留路径只读兼容 + 懒迁移 | 旧 URL 继续可读；有写时再规范化 |

清理策略建议：

- 引用源：商品 `images` JSON、Banner/广告表、会员 avatar、评价/售后 JSON、文章/活动 HTML 抽 URL  
- 宽限期：标记 orphaned 后 ≥ 30 天再删  
- 备份：清理前可按 `domain/type/Ymd` 打冷备（可选）

## 6. 实施分期（建议里程碑切片）

### A7.1 规范落地（小刀，无迁移）

1. 扩展 `ImageUploadService` 支持多段 bucket（如 `marketing/banner`）或 `domain + type`。  
2. 枚举白名单：仅允许上表类型。  
3. 改 Admin/H5 上传调用：文章→`content/article`，弹窗→`marketing/popup`，券→`marketing/coupon`，广告→`marketing/image_ad` 等。  
4. 管理端保存时按类型校验前缀。  
5. **读路径完全兼容旧 `/storage/product|banner|admin|...`**。

### A7.2 资产表 + 概览

1. Migration：`upload_assets`。  
2. `store()` 成功写索引。  
3. Admin 只读列表：类型、数量、体积、最近上传。

### A7.3 清理与可选迁徙

1. 引用收集器 + orphan 标记任务。  
2. 管理端「清理预览」确认后执行。  
3. （可选）脚本把仍被引用的旧路径 copy/rename 到新树并改 DB。

## 7. 兼容与发布注意

- 发版 zip **继续排除** `public/storage/`（现状不变）。  
- Nginx/VPS 无需改；仍走 `files` 代理即可。  
- HTML 富文本统一经 `toStoredHtml` → 相对 `/storage/...`（避免长期存 files 代理 URL）。  
- 验收：每类上传各 1 条，检查磁盘路径前缀 + DB URL + H5/Admin 展示。
