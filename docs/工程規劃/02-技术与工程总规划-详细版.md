## 1. 目标陈述

从零重建 SisterMart：面向香港的 H5 珠宝商城。  
**不以 Bagisto 为底座二开**；仅在个别技术点上参考旧项目实现方式。  
架构、模块、接口、页面与交易规则以新 PRD 为准。

交付形态：Monorepo，含需求文档、参考素材、ThinkPHP API、Vue3 H5、Vue3+Naive UI 后台，直至可上自建 VPS 发布。

| 参考图/素材 | 后期放入 `refs/` |
| Bagisto | 仅参考，不拷贝整仓进本仓库 |

### 2.1 技术细节（已收敛）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| ThinkPHP | **8.1.x** | 官方主维护；兼容 PHP 8.4/8.5 的维护版本线；API 统一由 `apps/api` 提供 |
| H5 构建 | Vite + Vue 3 + Vue Router + Pinia + **Vant 4** | 按需引入；品牌主题覆盖 CSS 变量 |

| 任务 | 定时任务：未支付关单、自动收货 | 不依赖用户停留页面 |
| 国际化 | 前端 i18n + 后端多语言字段/表 | 账号记住语言偏好 |

## 3. 一期 / 二期划分（按你的 Q4）

### 3.1 原则

1. **主要功能后端一期闭环**：真实可走通购物与履约主链。  
2. **其他辅助功能**：后端可二期完善；**前端 UI 一期先实现交互效果**（Mock 或半接真）。  
3. PRD 有明确规则的，实现时以 PRD 为准，不得用 Bagisto 默认行为覆盖。

### 3.2 一期后端必须闭环（主链）

对应验收一句话：

> 会员邮箱登录 → 双语浏览商品 → 加购 → 券/积分/余额参与下单 → **模拟支付成功** → 后台发货并录物流节点 → 用户确认收货或自动收货 → 可申请售后退款（原路模拟或退余额）。

| 模块 | 一期后端 |
| --- | --- |
| 账号 | 邮箱注册/登录/忘记密码；协议勾选；语言偏好；WhatsApp 接口占位 |
| 商品/分类/搜索 | 多语言、多 SKU、库存锁、角标、已售展示开关 |
| 购物车 / 确认订单 | 计算顺序：售价→券→积分→余额→运费 |
| 支付 | 模拟支付；超时关单释放库存/券/积分/余额 |
| 订单状态机 | 待付款→待发货→待收货→已完成 / 已关闭 / 已退款 |
| 物流 | 后台发货、运单号、手工轨迹节点 |
| 自动收货 | 定时任务按 PRD 规则 |
| 售后 | 仅退款 / 退货退款；审核；退余额或模拟原路 |
| 优惠券 | 领券、下单核销、关闭退回 |
| 积分 | 下单完成发放、抵扣（比例与上限可配置） |
| 余额 | 无充值；售后退余额、（分销转入可二期） |
| 地址 | 仅香港地址簿 |
| 运费 | 门槛包邮 / 固定运费 |
| 文章 | 协议与页脚文章多语言 |
| 后台 | 概览、商品、分类、订单、售后、会员基础、券、积分配置、文章、设置 |

### 3.3 产品要做、但允许「前端一期交互 + 后端二期补齐」的辅助能力

下列在产品上 **Q2=要**；工程上按 Q4：**H5/Admin 一期出页面与交互**，后端可二期做实或一期先 Mock。

| 编号 | 能力 | 前端一期 | 后端建议 |
| --- | --- | --- | --- |
| 2.1 | 一级分销 / 佣金 / 提现 | 分销相关 UI + Mock | **二期后端做实** |
| 2.2 | 秒杀 | 列表/详情/倒计时/仅立即购买 UI + Mock | **二期后端做实** |
| 2.3 | 积分商城 | 列表/兑换 UI | 二期后端（或接主商品标记后逐步做实） |
| 2.4 | 每日签到 | 签到日历 UI | 二期 |
| 2.5 | 分享浏览送积分 | 分享按钮与 `ref` 链接 UI | 二期计次 |
| 2.6 | 订单消息 + 系统消息 | 双列表、未读红点 UI | 订单状态消息建议一期；营销消息可二期 |
| 2.7 | 会员等级星级 | 个人中心展示 | **一期后端必做**（已确认） |
| 2.8 | 底栏外观配置 | 每次进页拉配置并渲染 | **一期后端必做**（已确认） |

## 4. Monorepo 模具结构

```text
SisterMart/
├── apps/
│   ├── api/                 # ThinkPHP：路由、领域服务、任务、权限
│   ├── h5/                  # 用户端 Vue3 SPA
│   └── admin/               # 运营后台 Vue3 + Naive UI
├── docs/
│   ├── 需求分析/             # PRD（已导入）
│   ├── 工程规划/             # 本文与后续里程碑拆解
│   ├── 接口/                 # 接口清单与约定
│   └── 验收/                 # 按 PRD §20 细化
├── refs/
│   ├── bagisto说明/          # 仅笔记：哪些点借鉴、哪些禁止照搬
│   ├── 素材/
│   └── 原型/
└── scripts/
```

应用内模块（开发启动时展开，此处先定边界）：

**api（按领域分包，示例）**

- `auth` / `member` / `catalog` / `cart` / `order` / `payment` / `promotion`（券） / `points` / `wallet` / `aftersale` / `shipping` / `content` / `message` / `distribution`（二期加重） / `system`（设置、底栏、多语言）

**h5（按 PRD 信息架构）**

- 布局：顶栏 + 底栏四键（配置化）  
- 账号、商城、交易、订单、营销、分销、内容、我的  

**admin（按 PRD §18 菜单）**

- 概览、商品、分类、订单、售后、会员、首页运营、秒杀、券、积分、分销、文章、消息、设置

## 6. 与 Bagisto 的关系（纪律）

| 可参考 | 不可做 |
| --- | --- |
| 登录/忘记密码/首页/详情的**体验路径** | 直接 fork 包结构当 SisterMart |
| 库存锁定、订单状态等**思路** | 把 Bagisto 默认支付/地址/游客结账带进来 |
| Vue3 + Vite 工程经验 | 后台继续用 Bagisto Admin |

参考笔记统一写在 `refs/bagisto说明/`，避免代码里散落「从 Bagisto 抄来」的隐式依赖。

## 7. 风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 真支付 / WhatsApp 未接 | 不能生产收款与短信式验证 | 一期模拟支付 + 邮件验证；接口预留 |
| Q2 全要 vs Q4 二期后端 | 范围膨胀 | 本文 §3 拆分；前端先交互 |
| 私有仓库云端无权访问 | 无法推送模具 | 授权 Cursor GitHub App 或临时公开 |
| 需求文件夹仅有一份 PRD | 缺原型/素材 | `refs/` 预留，你后期补 |
| ThinkPHP 版本未钉 | 脚手架反复 | M0 确认 TP 大版本 |
