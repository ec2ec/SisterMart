## 背景

M7 已提供雙列表 UI + 未讀紅點，但 API 走 `MockMarketingService`（`mock: true`）。  
M11–M14 已把秒殺 / 積分商城 / 分銷 / 簽到做實；消息是剩餘的主鏈 Mock 能力之一。

M13 關閉時記下的缺口「售後沖回已入帳佣金」**預設不納入 M15**（可作 M16）；若你要求合併，見文末可選包。

## 目标

1. 新增真實消息表，訂單狀態變更自動寫入「訂單消息」  
2. 系統消息可由後台（或 seed）發布；會員列表 / 已讀 / 未讀數讀庫  
3. H5 消息頁、Tab 紅點 `mock: false`  
4. 與現有 REST `/api/v1/messages*` 契約兼容（字段可擴、不拆前端主流程）

## 范围（可检查）

### A. 数据与服务

- [ ] 表 `member_messages`（或拆 `order_messages` + `system_messages`，二选一写进实现说明）  
  - 建议字段：`id`, `member_id`, `type`(order|system), `title`, `body`, `ref_type`, `ref_id`, `read_at`, `created_at`  
- [ ] `MessageService`：列表 / 未讀數 / 標記已讀（單條或全部）  
- [ ] 訂單生命週期寫入（至少）：下單成功、支付成功、發貨、確認收貨、關單、售後審核結果  
- [ ] 系統消息：後台創建 API 或 Admin 頁最小可用；seed 1～2 條演示  
- [ ] 回應統一帶 `mock: false`

### B. API（維持 `/api/v1`）

- [ ] `GET /messages`（可 `?type=order|system`）  
- [ ] `GET /messages/unread-count`  
- [ ] `POST /messages/read`（body：`ids[]` 或 `all=true` / `type`）  
- [ ] （可選）`POST /admin/messages` 發系統消息

## 验收清单（联查用）

1. 下單並 mock 支付 → 會員「訂單消息」出現對應兩條（或合併策略寫明），`mock: false`  
2. 後台發貨 → 新訂單消息；未讀數 +1；標記已讀後 unread 下降  
3. 系統消息列表可見 seed/後台新建內容  
4. 未登錄調消息接口 → 401；跨會員讀不到他人消息  
5. 回歸：購物車下單 / mock 支付 / 簽到仍可用
