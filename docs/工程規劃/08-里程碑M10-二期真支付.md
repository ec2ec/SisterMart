# M10 — 真支付适配层（二期启动）

| 项 | 内容 |
| --- | --- |
| 状态 | **进行中** |
| 前置 | M9 已关闭 |
| 原则 | 不破坏一期模拟支付；渠道可插拔；无商户密钥时不得假装已接通 |

## 目标

把「创建支付单 → 跳转/拉起渠道 → 异步回调 → 订单待发货」从 Mock 专用逻辑抽成 **PaymentChannel** 适配层，为 FPS / AlipayHK / WeChat HK 真对接预留同一契约。

## 交付物

1. `PaymentChannelInterface` + `PaymentChannelFactory`  
2. `MockPaymentChannel`（默认，行为与 M4/M5 一致）  
3. 真渠道 **Stub**（未配置密钥时返回明确错误码，不落假成功）  
4. 公开回调入口 `POST /api/v1/payment-callbacks/:channel`（验签钩子）  
5. `config/payment.php` + 环境变量清单  
6. 接口/验收文档  

## 验收清单

1. 未配置真密钥时，H5 仍可走 `mock-confirm` 完成模拟支付  
2. Factory 可按 `channel` + `PAYMENT_MODE` 解析到 Mock 或 Stub  
3. 回调路由存在；无效签名 / 缺配置返回统一错误信封（不改订单）  
4. 文档列出接通真渠道所需密钥与下一步（M11 实对接）  

## 明确不做（本里程碑）

- 不申请/不写入真实商户号到生产  
- 不改订单主状态机语义  
- 不做真秒杀 / 真分销（后续里程碑）  

## 门禁

模拟支付回归失败 → 不得合并；Stub 误把未配置渠道标为已支付 → 不得合并。
