# SisterMart 里程碑拆分与验收门禁

| 项目 | 内容 |
| --- | --- |
| 版本 | 0.1 |
| 日期 | 2026-10-14 |
| 原则 | 每完成一个里程碑 → **暂停 → 你我联合检查** → 确认百分百达成后再开下一里程碑 |
| 产品真源 | PRD v1.4 |
| 技术冻结 | ThinkPHP 8.1 · Vue3+Vant4 H5 · Vue3+NaiveUI Admin · MySQL · 模拟支付 |

---

## 使用方式

1. 当前只做 **M0** 的收尾确认（规划与仓库）。  
2. 每个里程碑有：**目标 / 交付物 / 验收清单 / 未完成不得进入下一项**。  
3. 验收结论三选一：`通过` / `有缺口需补` / `范围变更`。  
4. **不跳号**；辅助功能（秒杀/分销）按约定：前端交互可进对应里程碑，后端 Mock，真逻辑标为二期不挡主闭环。

## M1 — 三端脚手架

### 目标
`apps/api`、`apps/h5`、`apps/admin` 空应用可启动；MySQL 连通；统一环境变量约定。

### 交付物
- ThinkPHP 8.1 项目骨架（路由健康检查接口）
- Vite + Vue3 + Vant4 的 H5 空壳（示例页）
- Vite + Vue3 + Naive UI 的 Admin 空壳（示例页）
- `.env.example`、基础 README 启动说明
- （可选）最简 CI：lint/安装检查

### 验收清单
1. 本机/容器：`api` 返回健康检查 JSON  
2. `h5`、`admin` 浏览器可打开且无构建错误  
3. 三端目录与 Monorepo 约定一致  
4. MySQL 连接配置可切换环境  

### 门禁
任一端无法干净启动 → 不进入 M2。

## M2 — 账号与主框架

### 目标
会员邮箱注册/登录/忘记密码；协议勾选；语言偏好；H5 顶栏+底栏（**底栏配置接口一期后端**）；未登录可浏览、登录后回跳。

### 交付物
- 认证 API + Token  
- WhatsApp 验证码接口占位（不实发）  
- H5：登录/注册/忘记密码页（对齐 Bagisto 体验路径，规则按 PRD）  
- H5 布局：店名、搜索入口、收藏夹/消息入口、底栏四键（读配置）  
- Admin：管理员登录、底栏配置维护（双语文案、图标、颜色）  
- i18n：zh-HK / en 切换并记住账号偏好  

### 验收清单
1. 未勾选协议无法登录/注册  
2. 邮箱注册登录、忘记密码可用（邮件可用 log/测试驱动）  
3. 每次进入带底栏页拉取配置；失败有降级默认  
4. 语言切换后面板文案切换  
5. 登录/确认订单流程不显示底栏（可先做登录；确认订单页在 M4 再验）  

### 门禁
无 Token 鉴权或底栏配置不可用 → 不进入 M3。

## M3 — 商品与内容主数据

### 目标
运营可维护分类/商品（多语言、SKU、媒体、角标、已售展示开关）；H5 可分类、搜索、详情（含全屏看图交互）。

### 交付物
- Admin：分类树、商品编辑、SKU 价库存、文章（协议/页脚）  
- H5：分类页（左大类右子类）、列表、搜索、详情、商品卡（角标/收藏心形 UI）  
- 首页可先接轮播/展示区最小数据（或静态配置）  

### 验收清单
1. 不同 SKU 价格库存独立  
2. 双语商品名/详情随语言切换  
3. 分类页交互符合 PRD §9.0  
4. 图片全屏缩放/切换可用；视频不进缩放看图  
5. 库存为 0 时不可加购（可在 M4 与加购一起验，但接口需具备）  

### 门禁
后台无法上架可售 SKU、或 H5 详情核心路径不通 → 不进入 M4。

## M4 — 交易下单闭环（关键检查点）

### 目标
**必须登录**完成：购物车 → 确认订单（地址/券/积分/余额/运费）→ **模拟支付成功** → 订单变为待发货。

### 交付物
- 香港地址簿  
- 购物车（勾选、失效行、合计）  
- 确认订单计算顺序：售价→券→积分→余额→运费  
- 模拟支付 + 前端轮询/跳转结果页  
- 未支付超时关单（任务可先可手动触发）  
- 订单列表/详情（待付款可再付/取消）  

### 验收清单
1. 未登录无法提交订单  
2. 非香港地址无法保存  
3. 满门槛包邮 / 未满收固定运费  
4. 模拟支付后状态：待付款 → 待发货  
5. 实付为 0 时直接支付成功（按 PRD）  
6. 超时关闭释放库存并退回冻结的券/积分/余额  

### 门禁
**本里程碑未 100% 通过，不进入 M5。** 这是一期最重要闸门。

---

## M5 — 履约与售后

### 目标
后台发货+物流节点；用户确认收货；自动收货任务；售后退款（原路模拟或退余额）。

### 交付物
- Admin：发货、运单、轨迹节点、订单留言（进订单消息更佳）  
- H5：物流页、确认收货、售后申请/进度  
- 定时任务：自动收货（PRD 规则：支付满 N 天且已发货且未点售后）  
- 退款成功回补库存；整单退完→已退款  

### 验收清单
1. 发货后订单待收货；物流节点倒序可见  
2. 手动确认收货→已完成  
3. 自动收货规则用例通过（含「点过售后不自动完成」）  
4. 售后仅未完成可申请；退余额或模拟原路  
5. 已退款不计完成、不发下单积分/佣金（佣金二期，但积分规则要遵守）  

### 门禁
自动收货或售后主路径失败 → 不进入 M6（或仅允许并行做 M7 UI，但主闭环不算完成）。

## M6 — 营销与资产（主链相关）

### 目标
优惠券、积分（下单发放+抵扣）、余额（无充值）、**会员等级**完整可用；与 M4 计算联动回归。

### 交付物
- 领券中心 / 我的券；下单核销与关闭退回  
- 积分明细；抵扣比例与上限配置  
- 余额流水（退款入账、下单抵扣）  
- 会员等级按累计实付五档（可后台改阈值）  
- Admin：券、积分设置、会员资产调整（填原因）  

### 验收清单
1. 券/积分/余额与 M4 订单重跑金额正确  
2. 订单完成后发放下单积分；运费不计  
3. 等级随累计实付跨越门槛变化  
4. 无充值入口  

### 门禁
金额计算与 PRD 不一致 → 必须打回修补后再开 M7/M8。

## M7 — 辅助 UI + Mock（不挡主闭环）

### 目标
秒杀、分销、积分商城、签到、分享 `ref`、消息等：**前端可完整走交互**；后端 Mock 或空实现。

### 交付物
- 秒杀列表/详情 UI（仅立即购买；接 Mock）  
- 分销中心/下级/提现/海报 UI（Mock）  
- 积分商城、签到页 UI  
- 消息双列表 + 顶栏未读红点（订单消息尽量接真；营销可 Mock）  
- 分享按钮与带 `ref` 链接（绑定上级可 Mock）  

### 验收清单
1. 页面可进入、主按钮有反馈、无白屏  
2. 明确标注/文档说明「Mock，二期做实」  
3. 不影响 M4～M6 真实下单回归  

### 门禁
演示路径断裂 → 补 UI；**不要求**二期后端完成。

## M8 — 联调硬化与验收

### 目标
按 PRD §20 做系统验收；补齐幂等、权限、任务稳定性、双语走查。

### 交付物
- `docs/验收/` 勾选表（从 §20 拆用例）  
- 支付/退款/入账幂等测试说明  
- Admin 角色（超管/运营）最小权限  
- 已知问题列表（若有）  

### 验收清单
1. §20 适用项全部勾选或注明「二期/Mock」  
2. 主闭环回归全绿  
3. 无阻塞级缺陷  

### 门禁
存在阻塞级缺陷 → 不开 M9。
