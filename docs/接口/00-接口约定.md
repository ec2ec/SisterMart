# 接口约定

状态：M2 起冻结。所有业务接口必须遵守本节的 RESTful 结构；与旧式 `{ "ok": true }` 或动词路径不兼容。

## 1. 总则

- 后端唯一入口：`apps/api`（ThinkPHP 8.1）
- H5 / Admin 消费同一 API，鉴权用各自 Bearer 令牌
- 协议：HTTPS（本地开发可用 HTTP）
- 格式：`Content-Type: application/json; charset=utf-8`
- 版本前缀：业务接口一律挂在 `/api/v1`
- 支付一期仅模拟；秒杀 / 分销一期前端 Mock，后端二期

## 2. RESTful 路径

1. 路径用**复数名词**表示资源，不用动词。  
2. 动作用 HTTP 方法表达：`GET` 读、`POST` 创建、`PUT` 整资源替换、`PATCH` 部分更新、`DELETE` 删除。  
3. 子资源用层级：`/members/me/password` 一类写法仅在资源归属清晰时使用；匿名重置密码用独立资源 `member-passwords`。  
4. 集合过滤用 query：`?page=1&per_page=20&status=1`（后续列表统一）。  
5. 不在路径里写文件后缀（不用 `.json` / `.html`）。

| 方法 | 路径 | 说明 |

## 3. 统一响应信封

成功与失败都使用同一顶层结构，业务数据只放在 `data`：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number | 业务码。`0` 表示成功；非 `0` 表示失败 |
| `message` | string | 给人看的说明，可直接展示或记日志 |
| `data` | object \| array \| null | 成功时的资源体；失败时为 `null`，或带少量补充字段 |
| `error` | object \| 省略 | 仅失败时出现 |

失败示例：

```json
{
  "code": 42201,
  "message": "請先閱讀並同意用戶協議和私隱協議",
  "data": null,
  "error": {
    "name": "NEED_AGREE",
    "details": {}
  }
}
```

调试环境发送验证码成功时，`data.debug_code` 可带 6 位码；生产不返回该字段。

### HTTP 状态码

| HTTP | 场景 |
| --- | --- |
| 200 | 读取成功、更新成功、删除成功、登录成功 |
| 201 | 资源创建成功（注册、发验证码） |
| 400 / 422 | 参数或业务校验失败 |
| 401 | 未登录或令牌无效 |
| 403 | 已登录但无权限 / 账号停用 |
| 404 | 资源不存在 |
| 429 | 发送过频等限流 |
| 500 / 503 | 服务或依赖失败 |

客户端必须以 **`code === 0`** 判定业务成功；同时可参考 HTTP 状态。不要再读取已废弃的 `ok` 字段。

### 业务码分段

| 段 | 含义 |
| --- | --- |
| `0` | 成功 |
| `400xx` | 请求参数 / 校验 |
| `401xx` | 未鉴权 |
| `403xx` | 禁止 |
| `404xx` | 未找到 |
| `422xx` | 业务规则不满足 |
| `429xx` | 限流 |
| `500xx` | 服务端 |

`error.name` 为稳定机器码（如 `BAD_PASSWORD`、`WHATSAPP_UNAVAILABLE`），前端可做文案映射。

## 4. 鉴权

```
Authorization: Bearer <token>
```

- 会员令牌与管理员令牌分表，互不通用
- 需要登录的接口未带令牌或令牌失效：HTTP 401，`error.name = UNAUTHORIZED`
- 退出登录：`DELETE .../sessions/current`，服务端删除当前令牌
